# Захват реальных механизмов удаления amo через браузер

**Решение владельца (22.07.2026):** удаление сущностей в amo в 99-100% случаев идёт через **приватное
ajax-API**. Публичный v4 либо не имеет роутов удаления вовсе, либо отдаёт 403/404/405 — это подтверждено
эмпирически в `.superpowers/sdd/task-4-spike.md`. Поэтому механизмы не подбираются перебором, а
**снимаются с браузера**: смотрим, что реально шлёт UI amoCRM, и повторяем запрос, мимикрируя под клиента.

Авторизацию предоставляет владелец. До этого момента план ниже — заготовка.

## Инструмент

`agent-browser` (skill `~/.claude/skills/agent-browser/`, бинарь per-machine). Headless работает в WSL2.
Ключевое для задачи — команда `network requests`: она отдаёт список запросов страницы, включая XHR,
с методом, URL, заголовками и телом.

## Процедура на один тип сущности

1. `agent-browser open https://pushka.amocrm.ru/leads/pipeline/` (или соответствующий раздел).
2. `agent-browser snapshot -i -c` — получить интерактивные refs (`@e1`, `@e2`, …).
3. Выделить тестовую сущность → открыть контекстное меню → «Удалить» → подтвердить.
   Каждый шаг — `click @eN` по ref'ам из снапшота.
4. `agent-browser network requests` — снять список запросов, отфильтровать XHR к `/ajax/`.
5. Зафиксировать: **метод**, **URL**, **content-type** (form vs json), **точное тело запроса**,
   значимые заголовки (`X-Requested-With`, CSRF-токен, если есть), **тело ответа**.
6. Отдельно проверить семантику: после удаления сущность в корзине или снесена насовсем.
   Для лидов — сверить `withOnlyDeleted()`.

## Что нужно снять (список из спайка)

| Тип | Что именно выяснить |
|---|---|
| tasks | чем UI удаляет задачу (публичного delete нет: 403 `Invalid scope`) |
| notes | чем UI удаляет примечание (публичный роут отдаёт 405) |
| catalogElements | прямое удаление элемента каталога (ajax-кандидат дал `Код ошибки 222`) |
| unsorted | как UI **отклоняет без создания лида** — сейчас `decline()` порождает реальный лид в скрытом пайплайне |
| calls | удаляется ли звонок из карточки вообще |
| shortLinks | адресуемы ли короткие ссылки (в ответе `create()` нет `id`) |
| leads/contacts/companies | чем UI сносит **насовсем**, а не в корзину; и как чистится сама корзина |

## Гигиена

- Удалять только сущности, созданные под захват (префикс `sp0-spike-` / `capture-`).
- Учётные данные владельца **не сохранять** ни в файлы репозитория, ни в скратчпад. Если понадобится
  повторный вход — просить заново.
- После сессии гасить демон: `agent-browser close --all`.

## Почему это важно для новой архитектуры

Захваченные запросы — не деталь тестовой инфраструктуры, а **контракт приватного канала**, который новая
библиотека обязана изолировать явно (отдельный слой, версионирование, деградация при изменении UI amo).
Публичный v4 и приватный ajax имеют разную стабильность и разные форматы ошибок — смешивать их в одном
неразличимом API нельзя.
